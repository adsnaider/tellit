# commenter

`commenter` is a local code review commenting CLI for Jujutsu (`jj`) repositories. It persists discussion threads as structured JSON files organized by Jujutsu change IDs and Git commit hashes.

## Storage Layout

The default store resolves to `<main-repo>/.comments` (even inside Jujutsu workspaces).
The file hierarchy follows:

```
<store>/[jj change ID]/[git commit hash]/[thread-id].json
```

Each thread file has the schema:

```json
{
  "filepath": "path/to/file.ext",
  "line_range": {
    "start": 10,
    "end": 20
  },
  "comments": [
    "Initial review comment",
    "Reply 1",
    "Reply 2"
  ],
  "resolved": false
}
```

- `filepath`: Relative path from the repository root.
- `line_range`: `{ "start": u32, "end": u32 }` (omitted for whole-file comments).
- `comments`: Ordered list of comment strings.
- `resolved`: Boolean flag indicating if the thread is resolved.

## CLI Usage

### 1. Adding a Comment (`add`)

Creates a new comment thread with an autogenerated UUID v4.
Only outputs the generated `thread-id` to `stdout`. All logs/diagnostics go to `stderr`.

```bash
commenter add --file <FILEPATH> --content "<COMMENT>" [--at <RANGE>] [-r <REV>]
```

- `--file`, `-f`: Target file path (relative to repo root or current directory).
- `--content`, `-c`: The comment text.
- `--at`, `-a` (optional): Line range. Supports:
  - Single line: `42`
  - Range: `10..20`, `10..=20`, `10-20`, `10:20`
- `-r`, `--rev` (optional): Jujutsu revision (defaults to `@` or global `-C/--change`).

**Example:**
```bash
THREAD_ID=$(commenter add --file src/main.rs --at 15..25 --content "Consider handling the Err variant here")
```

---

### 2. Replying to a Comment (`reply`)

Appends a new reply to an existing comment thread.

```bash
commenter reply --thread <THREAD_ID> --content "<REPLY>"
# Or positional:
commenter reply <THREAD_ID> "<REPLY>"
```

- Supports exact UUID or prefix matching (e.g. `commenter reply 7a3c9558 "Fixed in latest commit"`).

---

### 3. Resolving / Unresolving a Comment (`resolve`)

Marks a thread as resolved (default) or unresolved.

```bash
# Resolve:
commenter resolve --thread <THREAD_ID>
commenter resolve <THREAD_ID>

# Unresolve:
commenter resolve --thread <THREAD_ID> --unresolve
commenter resolve <THREAD_ID> --unresolve
```

- Supports exact UUID or prefix matching.

---

### 4. Querying Comments (`get`)

#### Get Thread Details (JSON)
Returns complete information about a thread, including Jujutsu change ID, commit ID, and git commit hash:

```bash
commenter get thread <THREAD_ID>
```

**Output:**
```json
{
  "thread_id": "7a3c9558-a236-4008-b80a-65255a78a96f",
  "change_id": "sytvsputuwmsywpmsukqutzyqzwvstxv",
  "commit_id": "b0ca354654415db7079911fb3dd41f884fbcaeea",
  "git_commit_hash": "b0ca354654415db7079911fb3dd41f884fbcaeea",
  "filepath": "src/main.rs",
  "line_range": {
    "start": 15,
    "end": 25
  },
  "comments": [
    "Consider handling the Err variant here",
    "Fixed in latest commit"
  ],
  "resolved": true
}
```

#### Get Git Commits for a Jujutsu Change ID
Lists all git commit hashes that contain comments under a given Jujutsu change ID:

```bash
commenter get change <CHANGE_ID> [--json]
```

#### Get Thread IDs for a Git Commit Hash
Lists all thread IDs associated with a specific git commit hash:

```bash
commenter get commit <GIT_COMMIT_HASH> [--json]
```

---

## Global Options

- `-s`, `--store <PATH>`: Custom store directory. When omitted, automatically resolves `<main-repo>/.comments` using `jj root` and `.jj/repo`.
- `-C`, `--change <REV>`: Target Jujutsu revision (defaults to `@`).

## Common Agent Review Workflows

### Addressing Review Feedback
1. Find threads for the current revision:
   ```bash
   COMMIT_HASH=$(jj-for-agents log -r @ --no-graph -T 'commit_id')
   THREADS=$(commenter get commit "$COMMIT_HASH")
   ```
2. Inspect each thread:
   ```bash
   commenter get thread <THREAD_ID>
   ```
3. Make the necessary code edits.
4. Reply and resolve:
   ```bash
   commenter reply <THREAD_ID> "Addressed in this commit"
   commenter resolve <THREAD_ID>
   ```
